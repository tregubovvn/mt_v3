# mt_v3 — единый редактор XML-заданий

Один редактор вместо трёх: **rt_v2** (Reading Test), **mt_v2** (Moodle Quiz) и
**ft_v2** (Formula Test). Общие функции собраны в одно ядро, а для каждого типа XML
работает свой редактор формы.

```
https://tregubovvn.github.io/mt_v3/index.html
```

Тестирование встроено в mt_v3 — единая точка входа `test/index.html?file=…`
(одно окно ФИО + Группа, тип определяется по корню XML):

| Тип | Корень XML | Редактор формы | Тестирование |
|---|---|---|---|
| Reading Test | `<readingTest>` | тема, фрагменты, вопросы choice/input | `test/rt/index.html` |
| Moodle Quiz | `<quiz>` | вопросы multichoice / truefalse / shortanswer / numerical / description | `test/mt/index.html` |
| Formula Test | `<formulas>` | формулы LaTeX, условные обозначения, предпросмотр и фрагменты | `test/ft/index.html` |

## Что единое, а что разное

**Единое (ядро `app.js`):**

- открытие файла с диска и из GitHub Gist, автоопределение типа по корню XML;
- сохранение в файл и автосохранение (File System Access API, Chromium);
- публикация в GitHub Gist, GitVerse и на свой сервер (`publish.php`);
- сборка ссылки на задание с флагами CheckMode / ShowHeader / CrushMode / RandomMode;
- режимы и промпты: окно выбора, свои режимы, один Gist на все режимы;
- DeepSeek: активный промпт + XML → ответ модели → разбор и применение;
- настройки и токены, статусная строка, проверка XML перед публикацией.

**Разное (адаптеры `editors/*.js`):**

- разбор и сборка XML своего формата;
- форма редактирования под структуру задания;
- проверки (валидация) и подсказки;
- приложение тестирования, префикс серверной публикации и набор базовых промптов.

## Структура

```
mt_v3/
├── index.html          — оболочка: панель, вкладки типов, XML-панель, модальные окна
├── app.js              — ядро: файлы, публикация, промпты, AI, настройки
├── styles.css          — общие стили
├── editors/
│   ├── registry.js     — реестр типов и автоопределение по корню
│   ├── rt.js           — Reading Test
│   ├── mt.js           — Moodle Quiz
│   └── ft.js           — Formula Test
├── vendor/
│   ├── file-api.js     — из save_api: загрузка/сохранение/публикация
│   ├── prompts-api.js  — из save_api: режимы и промпты + окно выбора
│   ├── xml.js          — минимальный XML-разбор (работает и в Node)
│   └── latex-fragments.js — разбиение формулы на фрагменты (как в ft)
└── tests/formats.test.js — разбор/сборка/round-trip всех трёх форматов
```

Сборки нет: статические файлы, любой современный браузер.

## Запуск

```bash
python -m http.server 8080
# http://localhost:8080/index.html
```

Через `file://` страница откроется, но диалоги сохранения файла могут быть
недоступны — сохранение уйдёт в скачивание.

## Настройки и токены

⚙ Настройки:

- **GitHub Token** — Gist и чтение приватных Gist'ов;
- **GitVerse Token** — публикация файла в репозиторий;
- **Пароль сервера** — публикация на `publish.php`;
- **DeepSeek Token** — кнопка «✨ DeepSeek»; запрос к DeepSeek можно отменить кнопкой «Отменить» в окне ожидания.
- адрес `publish.php` и папка архива — при необходимости.

Токены хранятся в `localStorage` браузера. На каждый тип XML создаётся свой
экземпляр `file-api`, поэтому привязка Gist/файла и ссылка на задание не
пересекаются между типами.

## Начало работы

- **«＋ Новое»** открывает пустое задание, в котором уже есть один пустой элемент
  (фрагмент / вопрос / формула) — можно сразу печатать в форму справа.
- В XML-панели при этом только подсказка «XML пока пуст». Как только вы начинаете
  печатать в форме или в самом поле XML — подсказка исчезает, а XML собирается сам.
  В подсказке есть кнопки «Загрузить пример» и «Вставить из буфера».
- **«Пример»** (рядом с «Копировать») загружает демонстрационный XML для выбранного
  типа — удобно посмотреть структуру и потренироваться.
- Название текущего режима видно в шапке редактора: **«Reading Test — Промпт для
  создания заданий READ»**; оно меняется вместе с режимом.
- Удалять можно любые элементы, включая последние: фрагмент, вопрос, вариант,
  ответ, формулу, обозначение. Подтверждение — своё окно (не системный `confirm`,
  который браузеры умеют блокировать), после удаления показывается уведомление.
  Когда список опустел, в форме остаётся empty-state с кнопками добавления.

## Метаданные

Автор, университет, дисциплина и аудитория хранятся в `localStorage` (как в
редакторе rt_v2) и подставляются в новое задание любого типа:

- **Reading Test** — теги `<author>`, `<university>`, `<discipline>`, `<targetAudience>`;
- **Formula Test** — тег `<meta author discipline university audience />`;
- **Moodle Quiz** — тема (`topicName`) и метаданные попадают в **первый вопрос-описание**
  (`type="description"`), который генерируется автоматически и не редактируется
  в списке вопросов.

Если открыть XML с заполненными метаданными, они запоминаются и подставляются в
следующие задания.

## Публикация

Открывается кнопкой «🚀 Публикация»:

- **GitHub Gist** — создаёт или обновляет Gist с файлом типа
  (`reading_test.xml`, `quiz.xml`, `formula_test.xml`);
- **GitVerse** — коммитит файл в репозиторий;
- **Свой сервер** — `publish.php`, имя файла `<Тип>_<10 цифр>.xml`, тип берётся
  из редактора: `ReadTest`, `MoodleTest`, `FormulaTest`.

Ссылка на задание собирается под конкретное приложение тестирования; флаги
добавляются в URL. Проверка XML выполняется перед публикацией: некорректный XML
не уйдёт.

## Режим просмотра

Кнопка **«👁 Просмотр»** в шапке редактора показывает задание так, как его увидит
студент:

- **Reading Test** — текст фрагмента и все его вопросы с вариантами и полями ввода;
- **Moodle Quiz** — вопрос с вариантами, полем короткого ответа или числа;
  HTML и LaTeX рендерятся MathJax (поддерживаются оба варианта записи: `\( … \)`
  и `\\( … \\)`);
- **Formula Test** — название формулы, условные обозначения и фрагменты для сборки
  в перемешанном порядке (как в тестирующем приложении); KaTeX показывает
  обозначения, а по флажку — и саму формулу.

Переключение между вопросами — кнопки ← → или стрелки клавиатуры, счётчик
показывает позицию. Флажок **«правильные ответы»** подсвечивает верные варианты
и эталонные ответы — это уже авторский режим. Выход — «К редактору» или Esc.

## Режимы и промпты

«📝 Режимы» открывает большое окно `prompts-api`. Все промпты всех трёх редакторов
хранятся в **одном файле `prompts.xml`** на GitHub Gist
([gist](https://gist.github.com/tregubovvn/2f9804a3ad5439b1bb60957b8969826a)):
у каждого промпта — название режима, вид теста (`rt` / `mt` / `ft`) и Markdown-текст:

- редактор показывает промпты своего вида теста;
- чтение — публичное, без токена: все режимы видны всегда, текст кэшируется
  в `localStorage` на случай сбоя сети;
- правка (название, вид теста, текст, добавление, удаление) и сохранение в Gist —
  при подключённом GitHub Token;
- «Применить режим» переключает режим редактора, «💾 Сохранить в Gist» записывает
  все промпты обратно в один XML;
- файл можно править и руками на gist.github.com — текст каждого промпта лежит
  внутри CDATA, а в шапке файла есть комментарий-подсказка о формате.

## Проверка

```bash
node tests/formats.test.js
```

11 проверок: XML-парсер, round-trip (разбор → сборка → разбор) для всех трёх
форматов, типы вопросов Moodle, формулы с обозначениями, ошибки валидации.

## Важно про деплой

Workflow `.github/workflows/main.yml` копирует репозиторий на сервер. В форке
mt_v2 путь был `/var/www/html/mt_v2`; для mt_v3 он должен быть
`/var/www/html/mt_v3` — иначе деплой перезапишет сайт mt_v2.

В этом PR файл workflow не менялся: у токена публикации нет scope `workflow`.
Поправьте `target` вручную до первого мержа/деплоя.

## Наследие

Репозиторий создан как копия mt_v2, поэтому в `editor/` остался старый
Moodle-редактор, а `tmp/` — его служебные файлы. Новый редактор живёт в корне
(`index.html`, `app.js`, `styles.css`, `editors/`, `vendor/`). Старую папку
`editor/` можно удалить, когда mt_v3 будет проверен на сайте.

## Ограничения

- Moodle: поддерживаются multichoice, truefalse, shortanswer, numerical,
  description; вложенные cloze/subquestions не редактируются (остаются в XML
  как есть при ручной правке, но форма их не показывает).
- Formula Test: предпросмотр через KaTeX подключается с CDN; без сети
  показывается исходный LaTeX, сборка фрагментов работает.
- Автосохранение в выбранный файл — только Chromium (File System Access API);
  в Firefox/Safari сохранение идёт через скачивание.
