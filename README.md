# mt_v3 — единый редактор XML-заданий

Один редактор вместо трёх: **rt_v2** (Reading Test), **mt_v2** (Moodle Quiz) и
**ft_v2** (Formula Test). Общие функции собраны в одно ядро, а для каждого типа XML
работает свой редактор формы.

```
https://tregubovvn.github.io/mt_v3/index.html
```

Тестирование остаётся на отдельных страницах — редактор только готовит XML и
собирает ссылку на нужное приложение:

| Тип | Корень XML | Редактор формы | Тестирование |
|---|---|---|---|
| Reading Test | `<readingTest>` | тема, фрагменты, вопросы choice/input | `rt_v2/index.html?file=…` |
| Moodle Quiz | `<quiz>` | вопросы multichoice / truefalse / shortanswer / numerical / description | `mt_v2/index.html?name=…` |
| Formula Test | `<formulas>` | формулы LaTeX, условные обозначения, предпросмотр и фрагменты | `ft/index.html?file=…` |

## Что единое, а что разное

**Единое (ядро `app.js`):**

- открытие файла с диска и из GitHub Gist, автоопределение типа по корню XML;
- сохранение в файл и автосохранение (File System Access API, Chromium);
- публикация в GitHub Gist, GitVerse и на свой сервер (`publish.php`);
- сборка ссылки на задание с флагами CheckMode / ShowHeader / CrushMode / RandomMode;
- режимы и промпты: окно выбора, свои режимы, один Gist на все режимы;
- DeepSeek: активный промпт + XML → ответ модели → разбор и применение;
- настройки и токены, статусная строка, проверка XML перед публикацией.

**Разное (адаптеры `editors/*.js`):**

- разбор и сборка XML своего формата;
- форма редактирования под структуру задания;
- проверки (валидация) и подсказки;
- приложение тестирования, префикс серверной публикации и набор базовых промптов.

## Структура

```
mt_v3/
├── index.html          — оболочка: панель, вкладки типов, XML-панель, модальные окна
├── app.js              — ядро: файлы, публикация, промпты, AI, настройки
├── styles.css          — общие стили
├── editors/
│   ├── registry.js     — реестр типов и автоопределение по корню
│   ├── rt.js           — Reading Test
│   ├── mt.js           — Moodle Quiz
│   └── ft.js           — Formula Test
├── vendor/
│   ├── file-api.js     — из save_api: загрузка/сохранение/публикация
│   ├── prompts-api.js  — из save_api: режимы и промпты + окно выбора
│   ├── xml.js          — минимальный XML-разбор (работает и в Node)
│   └── latex-fragments.js — разбиение формулы на фрагменты (как в ft)
└── tests/formats.test.js — разбор/сборка/round-trip всех трёх форматов
```

Сборки нет: статические файлы, любой современный браузер.

## Запуск

```bash
python -m http.server 8080
# http://localhost:8080/index.html
```

Через `file://` страница откроется, но диалоги сохранения файла могут быть
недоступны — сохранение уйдёт в скачивание.

## Настройки и токены

⚙ Настройки:

- **GitHub Token** — Gist и чтение приватных Gist'ов;
- **GitVerse Token** — публикация файла в репозиторий;
- **Пароль сервера** — публикация на `publish.php`;
- **DeepSeek Token** — кнопка «✨ DeepSeek»;
- адрес `publish.php` и папка архива — при необходимости.

Токены хранятся в `localStorage` браузера. На каждый тип XML создаётся свой
экземпляр `file-api`, поэтому привязка Gist/файла и ссылка на задание не
пересекаются между типами.

## Публикация

Открывается кнопкой «🚀 Публикация»:

- **GitHub Gist** — создаёт или обновляет Gist с файлом типа
  (`reading_test.xml`, `quiz.xml`, `formula_test.xml`);
- **GitVerse** — коммитит файл в репозиторий;
- **Свой сервер** — `publish.php`, имя файла `<Тип>_<10 цифр>.xml`, тип берётся
  из редактора: `ReadTest`, `MoodleTest`, `FormulaTest`.

Ссылка на задание собирается под конкретное приложение тестирования; флаги
добавляются в URL. Проверка XML выполняется перед публикацией: некорректный XML
не уйдёт.

## Режимы и промпты

«📝 Режимы» открывает большое окно `prompts-api`:

- выпадающий список режимов и предпросмотр промпта, который будет использован;
- «Применить режим» переключает режим редактора (название режима — `# Заголовок`
  промпта);
- свои режимы добавляются и правятся здесь же, все сохраняются в один Gist;
- без GitHub Token доступны только два базовых режима типа.

У каждого типа свой набор базовых промптов: у RT — «Абзацы» и «Предложения»,
у MT — «Тесты с формулами» и «Создание задач», у FT — «Формулы» и «Задачи».
Пользовательские режимы лежат в общем Gist и видны во всех трёх редакторах.

## Проверка

```bash
node tests/formats.test.js
```

10 проверок: XML-парсер, round-trip (разбор → сборка → разбор) для всех трёх
форматов, типы вопросов Moodle, формулы с обозначениями, ошибки валидации.

## Важно про деплой

Workflow `.github/workflows/main.yml` копирует репозиторий на сервер. В форке
mt_v2 путь был `/var/www/html/mt_v2` — **исправлено на `/var/www/html/mt_v3`**,
иначе публикация mt_v3 перезаписала бы сайт mt_v2.

## Наследие

Репозиторий создан как копия mt_v2, поэтому в `editor/` остался старый
Moodle-редактор, а `tmp/` — его служебные файлы. Новый редактор живёт в корне
(`index.html`, `app.js`, `styles.css`, `editors/`, `vendor/`). Старую папку
`editor/` можно удалить, когда mt_v3 будет проверен на сайте.

## Ограничения

- Moodle: поддерживаются multichoice, truefalse, shortanswer, numerical,
  description; вложенные cloze/subquestions не редактируются (остаются в XML
  как есть при ручной правке, но форма их не показывает).
- Formula Test: предпросмотр через KaTeX подключается с CDN; без сети
  показывается исходный LaTeX, сборка фрагментов работает.
- Автосохранение в выбранный файл — только Chromium (File System Access API);
  в Firefox/Safari сохранение идёт через скачивание.
